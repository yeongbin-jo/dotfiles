---
name: preflight
description: Personal pre-PR gate for autodrive. Run BEFORE every push/PR to make CI's fresh-model reviewer a true FINAL gatekeeper instead of the first place gaps surface. Two parts — a deterministic local mirror of CI's own gates (thin wrapper, never a reimplementation) + an INDEPENDENT seam review that turns every external assumption the change makes into an executed probe against its real source of truth (no harness substitution at the seam). Validated by a 3-lens neutral panel (ROI + false-confidence + completeness) against two real misses (a CDK task-def missing an env var the runbook needed; a skill pointing at an unregistered MCP tool that a hand-fed dogfood masked). Invoke from autodrive's pre-PR step; also usable standalone before any push.

# preflight — pre-PR gate (personal)

## Read first — what this is and is NOT
- **Local-green is NECESSARY, NOT SUFFICIENT — and the aim is to catch as much as possible LOCALLY, not to wait for CI to spoon-feed the hard class.** Reach CI with as little left to catch as possible. CI's fresh-model reviewer (codex) stays the REQUIRED final net; local-green is never permission to skip or under-weight it, and you never optimize to "pass preflight" — you optimize to catch the bug. What escapes a genuinely-independent local pass is codex's job; the cheap and the probeable are yours.
- **Independence CAN be pulled in-house — but only if the local pass is ACTUALLY independent.** What Goodharts is a *same-model, same-context self-review* (self-attack is correlated with self-error) — not local review as such. So don't "wait for codex"; run the local review as a genuinely independent pass: a DIFFERENT model where possible (local `codex exec … < /dev/null`, or another vendor), else a clean-context subagent that did NOT author the diff, and run it **recall→refute** (pass 1 finds everything, pass 2 filters false positives). CI codex remains the out-of-band backstop for the blind spots a same-vendor local pass still shares — you just stop handing it the cheap stuff.
- **One principle underpins the whole gate:** *verify every external contract against its real source of truth, and never let the test harness (fixture / mock / hand-fed payload) stand in for a real dependency.* Both historical misses collapse to this one sentence.

## Part 1 — Deterministic mirror (a SCRIPT, not a checklist)
Before every push, run the SAME gates CI runs, by invoking the repo's own shared scripts — **never reimplement a check with different logic** (a divergent local check that false-greens is worse than none; single source of truth = zero drift). A script removes the *skip option* that caused past misses ("didn't run bundle-fresh until CI forced it"). A checklist item ("did you run X?") leaves the option open — don't.

Resolve the repo's real gate commands from `.github/workflows/*` and run the fast/deterministic ones locally:
- **build — the REAL CI type gate** (`pnpm build` = tsc emit + `next build`; gate `next build` on dashboard-touching diffs, else libs-only). `typecheck` alone is a *divergent proxy* CI does not run — it green-lights emit-only / `next build` errors that then fail CI's `Build` (the #1 real blocker in the 30-day audit, 12/17). Post-RND-2827 `turbo build`/`typecheck` `dependsOn ["^build","generate"]`, so a cold run self-heals (builds packages + regenerates the Prisma client) instead of false-passing.
- **lint** (the repo's `@vb-crosscheck/eslint-rules` gate) — mechanically-catchable anti-patterns live here as **AST rules**, NOT as a prose checklist the reviewer reads; a rule can't be skipped or Goodharted the way a checklist item can. When a new mechanically-catchable anti-pattern recurs, add it as an eslint-rule / a `schema.prisma`/migration check (repo), per Part 3 — reuse the existing rule package, do not stand up a second scanner.
- **live-contract probe — the one class local beats codex on** (run when the diff touches an external contract; see the `contract-vs-real-external-system` seam class in Part 3): exercise the changed contract against its REAL source pre-PR (SuiteQL → `LIMIT 0` on the sandbox; a route → local-stack smoke), never a mock.
- **affected tests** (skip the slow full-suite / e2e — CI owns those; a heavy pre-push gate gets bypassed)
- **leak / denylist scan** — if the change touches a public-surface tree (run the repo's denylist against source AND any committed bundles)
- **bundle-fresh** — if the change touches a bundled artifact: rebuild from source and assert byte-match (install the builder if missing; the stale bundle is the runtime)
- **release invariants for the touched area** — e.g. a plugin content change bumps the version in BOTH the plugin manifest and the marketplace entry (they must agree); regenerate any wrappers/adapters
- **policy / spec-ref** — a spec-lineage signal in title/body/branch/changed-spec-path, or the correct exempt label (`no-spec` / `chore` / `typo`)

If a gate genuinely cannot run locally, **say so explicitly** — do not assume it passes.

**crosscheck concretes (example):** `pnpm build` (dashboard-gated `next build`) — NOT `pnpm typecheck` alone; `pnpm lint`; `pnpm test` (or affected); the leak scan = grep source + `*.bundle.mjs` against `plugins/lens/leak-denylist.json` (excludes: node_modules, the denylist file, the boundary ADR); `cd plugins/lens && node --test test/bundle-fresh.test.mjs` after `npm run build:server && build:auth`; plugin version bump in `.claude-plugin/plugin.json` + root `.claude-plugin/marketplace.json`; `no-spec` label when there is no `.specify/specs/<id>` dir.

## Part 2 — Independent seam review (JUDGMENT — the high-value part)
Spawn the pre-PR adversarial reviewer as an INDEPENDENT pass: **fresh context, a DIFFERENT model where possible.** A same-model self-review rationalizes the exact way the author-agent did — self-attack is correlated with self-error. The reviewer must produce a **verifiable ARTIFACT, not a verdict**:

**Make it genuinely independent, then run it recall→refute.** The pass is worth trusting only if it does NOT share the author's context: a DIFFERENT model where possible (local `codex exec … < /dev/null`, or another vendor), else a clean-context subagent that did not author the diff. Run two passes — **pass 1 maximizes recall** (surface every candidate finding), **pass 2 refutes/filters** (a same-vendor pass over-fires; kill the false positives). Give it codex's own context recipe: `node scripts/extract-primary-spec.mjs` → feed `spec.md`/`plan.md`/`tasks.md` + the `AGENTS.md` ANTI-PATTERNS catalog, framed **per-acceptance-criterion** (✅ implemented / ⚠️ partial / ❌ missing, P0–P3). This is how you catch *here* what CI codex would otherwise be first to find — CI stays the backstop, never the first catcher. (Detection is the model, not the doc: same AGENTS.md, codex caught 8 incident-class bugs where CodeRabbit caught 0 — so a genuinely-independent, capable model is load-bearing; a weak local pass reading the same catalog gets CodeRabbit-tier recall while *looking* done.)

> **FIELD NOTE (measured 2026-07-02, first ~5 issues after adoption): the #1 real failure is skipping this step — "self-reviewing" in the author's own context instead of ACTUALLY spawning the independent pass.** When that happened, the "verify against real source" class went straight to the CI fresh-model reviewer *every time* (a schema map transcribed from prose instead of the real schema → wrong column + 3 missing tables; a gate's own file-type coverage; a doc's overclaim). Part 1 (the deterministic mirror) delivered its wins as designed; Part 2 delivered ~nothing **because it wasn't actually run as a separate agent.** Self-prompting "trace outward" does NOT substitute — it inherits your blind spots. **RUN THE SPAWN.**
>
> **Scope gate (when Part 2 is required):** whenever the change TRANSCRIBES or ASSERTS an external fact — mirrors a schema / allowlist / task-def, points to a tool / env var / table that must exist elsewhere, or IS a validator whose coverage is a claim. A pure prose / formatting / config-only change is adequately covered by Part 1 alone (data: the docs/gate-config PRs needed nothing more).

1. **Assumption ledger.** Enumerate every external existence/behavior the change ASSUMES — MCP tools, env vars, ECS task-def entries, secrets, IAM permissions, downstream consumers, release/version invariants, files it expects elsewhere — and for EACH, the concrete `file:line` / grep / probe that PROVES it against its **real source of truth**. An empty or hand-wavy ledger is a RED FLAG, not a pass. **If the change IS itself a validator / gate / scanner, verify its own COVERAGE** — does it actually cover every input it claims to (all file types, all cases)? A leak-gate that scanned only `.mjs` silently ignored the compiled `.js` bundle that is the real runtime. **And: anything the change TRANSCRIBES from a canonical source (schema columns, allowlist entries, table/tool names) must be DIFFED against that source programmatically — never eyeballed.** Transcribing a schema map from prose docs instead of from the Prisma schema + the query allowlist is exactly how a wrong column name and three missing tables reached CI; a 5-line "map ⊇ allowlist" assertion would have caught it locally.
2. **Execute, don't reason.** For every "call Y / uses Z / now points to W" in the diff or PR body, actually resolve/invoke it: the MCP tool must resolve in the real tool registry; the env var must be present in the deployed task-def; the command must run. A claim with no executed probe is **UNVERIFIED**, not passed. **Existence vs. behavior — the trap that keeps re-catching us:** a grep / `file:line` read IS a valid probe for *existence* (the column / env var / tool is there). But for anything **DERIVED or COMPUTED** — a serialization's wire shape, a transform's output, a defaulted/coerced value, a regex/cast result — reading the *declaration* verifies nothing, because the derivation rule (a serde attribute, a `??`/`||` default, a case convention, a coercion) is non-obvious and is *exactly* where reason-by-reading is wrong. Derived contracts must be **executed and their actual output inspected** (run the serialize, evaluate the expression, round-trip the value), and the fix ships with a test that pins the *output shape*, not one that asserts the source-side value is equal to itself. If you can't state whether a ledger row is existence or behavior, treat it as behavior and execute it.
3. **No harness substitution at the seam.** Any test / dogfood must exercise the **acquisition path** from the real source — **no fixture, mock, or hand-fed payload may occupy the exact seam the change creates.** (The dogfood that hand-fed the schema JSON validated "given the schema, downstream works" while the real claim was "the agent OBTAINS the schema by calling the tool" — the untested seam fell outside the fixture.) Rule: *inputs to a verification must come from the same channel production uses; if you typed it in yourself, that step is untested by definition.*
4. **The assumption ledger is NOT the whole artifact — run every triggered seam-class enumeration too.** The ledger (rules 1-3) proves EXTERNAL facts (does X exist / match / round-trip). It will pass a diff whose bug is **internal logic** — a concurrency race, a retryable-vs-terminal misclassification, a write keyed on an unverified identity, a fail-open on bad input. So the Part-2 artifact MUST ALSO include, explicitly, the enumeration for **every** Part-3 seam CLASS whose trigger the diff matches (crash-window/redelivery, conditional-skip, contract-vs-real, error-taxonomy, …). A thorough external ledger with the triggered enumerations *skipped* is an **incomplete Part-2**, not a pass — it is the measured way in-scope logic bugs still reach CI. (RND-2843: the diff tripped the crash-window/redelivery trigger (BullMQ worker + durable mapping/receipt transitions adjacent to VB mint+forward side effects), but the seam review ran only the existence ledger; CI codex then found the check-then-act double-egress (P1-c), the retryable-outage-as-terminal (P1-b/P2-a), and the fail-open body parse (P2-b) — all in-scope for classes already listed here.) Before pushing, state which class triggers fired and show each enumeration, or state "no class triggers matched."

## Part 3 — Feedback done right (so it doesn't rot)
When CI/codex catches something preflight missed, do NOT append a one-off script (a graveyard of instance-specific checks that overfit and go stale). Prefer, in order:
- a **mechanically-derived invariant** pushed into CI — e.g. "every env var referenced in code exists in the CDK task-def", "every MCP tool a skill references resolves in the real registry", "any change under a bundled plugin bumps the version". Self-updating, generalizes past the instance.
- else fold it into the ONE principle / the seam-class list above (keep it **flat** — prune stale entries; track seam CLASSES: tool, env var, task-def, secret, downstream consumer, version invariant, **conditional-skip/absent-result** — not literal instances).
  - **conditional-skip/absent-result** (added after RND-2816: two real deploy-safety edges reached CI because a single-angle review only modelled the happy path): whenever a downstream job/step treats a predecessor's `skipped` / absent / empty / defaulted result as *benign* (e.g. a GHA `if:` that accepts `needs.X.result == 'skipped'`, a `?? default`, a `|| fallback`), the seam review MUST enumerate **every** cause that predecessor can reach that state — the deliberate condition AND gate/predecessor failure AND each of its own `needs` failing AND forced-then-failed — and confirm each lands on the correct decision. The act/test harness only proves the scenarios you *modelled*; the ledger's job is to make the scenario set exhaustive. For high-blast-radius seams (deploy pipeline, migrate gate) this enumeration wants a *multi-angle* independent pass, not one reviewer — a single lens inherits one blind spot.
  - **crash-window / redelivery-idempotency** (added after RND-2823: a feature whose ENTIRE risk was crash-safety passed a green existence/contract ledger, then the independent CI reviewer found ~8 real edges it never modelled — each an instance of one of the four checks below, which are their general form). **Trigger:** the change adds a durable state transition adjacent to an external side effect (queue enqueue, RESTlet/HTTP POST, deploy, writing a claim/marker) OR a BullMQ worker / watchdog / lease / multi-writer row. For EACH such transition the ledger must answer, statically: (1) *process dies exactly here* → who recovers and within what BOUND (redelivery? a watchdog? a 90-min backstop that silently misses the tight bound the AC promised)? (2) *the job is redelivered* → is the idempotency guard checked BEFORE the side effect (claim-before-POST, not marker-after), and does it treat ALL terminal states as "already done" (not just pending/running — a completed job still counts)? (3) *two writers race* → is the transition a guarded compare-and-set (`updateMany … count===1`), not check-then-act? (4) *any filter in NEGATIVE position* (`NOT`, absent-key, `!=`) on a JSON path / nullable column is a NULL-semantics trap (`NOT(NULL)=NULL` → row excluded → reaps/matches 0) → rewrite as a positive `IN`/`equals` on an always-present field. This is STATIC crash-point enumeration, not a runtime-concurrency proof — most of these were plain logic/SQL bugs catchable pre-PR. And: **prove any reap/idempotency path against a REAL store, never an all-mocked queue/DB** — a mock returns the count you told it, so it green-lights the exact NULL/absent-key bug (CLAUDE.md's own "verify against real, not readFileSync/mocks" rule).
  - **contract-vs-real-external-system** (added after the 30-day escape audit — **4 of 6 post-merge escapes** were code calling a contract *no gate exercised live*: a SuiteQL `parent` column NetSuite doesn't have → failed every snapshot (#763); a CC-API route/param mismatch (#736); an App-Router path that renders no page → 404 email link (#707); a `/diff` call missing `workspaceId` whose `catch` fabricated `success:true` → UI showed "No drifted objects" (#766)). Unit tests passed *because they mocked the very seam that was wrong*, and **even CI codex misses these** — it reasons from repo text, it can't call NetSuite. **This is the one class a local probe beats codex on:** extract the external contract the diff touches and exercise it against the REAL source pre-PR — changed SuiteQL → `LIMIT 0` against the sandbox (VanZandt, **never Goodr**) so a bad column errors at parse; a changed API/App-Router route → boot the local stack and smoke-hit it (non-404, correct `{success,data}` envelope); a hand-maintained schema/catalog name → diff it against the landed Prisma model. A mocked seam here is not a check.
  - **error-taxonomy / retryable-vs-terminal** (added after RND-2843: CI codex found 3 real edges where a *transient/outage* failure was handled as a *terminal* result). **Trigger:** the diff catches an error or returns/propagates a `{success:false}` from an external or fallible call (HTTP to another service, a mint/lookup, a DB write, a queue op) inside a worker, a retry loop, a route, or a reducer. For EACH such failure the review must state its **class (retryable/transient vs terminal/expected)** and confirm the caller BRANCHES on it: (a) a transient failure must NOT be **persisted as** a terminal state (e.g. a VB lookup outage written as `unwired`/no-match, an empty fetch cached as "0 results") — that both corrupts state and skips recovery; (b) a BullMQ/worker handler must **throw** on a retryable failure so `attempts`/`backoff` actually run — resolving normally marks the job *done* and the retry policy never fires; (c) a route must fail loud (`{success:false}`/4xx-5xx) on a bad/absent input rather than **defaulting** it (a malformed body coerced to `{}` that silently picks `SYNC` is a silent-fallback, CLAUDE.md spec-103). The trap: `catch` / `if (!ok)` branches that collapse "the world is temporarily broken" and "the answer is legitimately empty/none" into one path.
  - **untrusted-key-write / shared-row blast-radius** (added after RND-2843 P1-a: a mismatch path wrote `unwired` to a *global account-keyed* mapping keyed on the environment's **unverified** `accountId`, letting a spoofed/misconfigured env flip a *victim* tenant's wired mapping and DoS its ingest). **Trigger:** the diff writes/updates a durable row whose KEY is an attacker-influenceable or unverified identifier (a free-text account id, a client-supplied tenant/workspace ref, a header) AND the row is shared across principals. Confirm: the write key is a **proven** identity (derived from authenticated creds / a verified join), and the not-verified / mismatch / error paths do **not** mutate the row for the *claimed* (unproven) key — they alarm or write principal-local state instead. A global upsert keyed on untrusted input is a cross-tenant integrity hole even when the value written looks benign.

Health metric: the list stays ~flat in size while covering more, because catches are being *generalized*, not *listed*.

**Escapes fold into this seam-class list (append-only) — never into a scored corpus you tune the local reviewer against.** A self-built, self-optimized bug set overfits to past shapes and manufactures a "we now cover codex" false confidence (worst on the items that are *codex's own* past catches). Keep any golden set append-only from real out-of-band catches; use it only to check you didn't re-break a known catch (a regression fixture), never as a metric to report (n is too small: precision is unmeasurable without a negatives pool) nor a target to tune toward.

## Scope honesty (state this; don't let green imply otherwise)
This gate is **pre-merge correctness**. It does NOT cover **true runtime / scale / prod-state**: an unindexed cascade delete that seq-scans a multi-million-row table under real data volume, an IAM policy that denies the action even though the env var exists, a migration that's unsafe against prod data distribution, timing/perf under load. Those are invisible to a static read — they belong to **Phase 5 (canary / staged rollout / prod-shaped dry-run)**. **Caveat (RND-2823):** do NOT let "concurrency = Phase 5" excuse skipping the crash-window/redelivery seam class above — the *static* enumeration of crash points and the NULL/absent-key and marker-ordering and check-then-act traps ARE pre-mergeable (they're logic/SQL bugs, not load-dependent races), and for a feature whose whole risk is crash-safety (queues, workers, watchdogs, idempotency) that enumeration is the point of the gate, not out of it. A green preflight must never imply the load-dependent tail is covered — but it should have exhausted the statically-reachable crash windows.
